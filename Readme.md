# FastAPI Library Service

Краткое описание: Сервис для управления библиотекой книг на FastAPI.

Технологии:
* Python 3.11+ / FastAPI & Pydantic v2
* PostgreSQL / SQLAlchemy 2.0 (Async) - База данных
* JWT (JSON Web Tokens) — аутентификация пользователей. Токены безопасно сохраняются в **HttpOnly, Secure Cookies**
* Redis - Blacklist сессии
* Docker / Docker Compose - Инфраструктура
* Alembic - Миграции
* Pytest - Тестирование

Как запустить проект

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/IliaTischenko/library-fastapi
   cd library-fastapi
   ```

2. **Создайте файл окружения:**
   Скопируйте пример конфига и заполните своими данными:
   ```bash
   cp .env.example .env
   ```

3. **Запуск приложения (Разработка):**
   ```bash
   docker compose --profile main up -d --build
   ```
   После этого API будет доступно по адресу: http://localhost:8000
   Документация Swagger: http://localhost:8000/docs

    > **Автоматическая инициализация: **
    > При самом первом запуске система автоматически проверяет наличие администраторов в базе данных.
    > Если в таблице `users` нет ни одного пользователя с ролью `admin`, бэкенд автоматически создаст суперпользователя с данными из вашего `.env` (`FIRST_ADMIN_USERNAME` и `FIRST_ADMIN_PASSWORD`).

   
Структура Базы Данных:

Проект использует реляционную модель данных (PostgreSQL) со следующими основными связями:

* **User (Пользователи)**: Хранит данные аккаунта (`id`, `username`, `hashed_password`, `role`). Связан с профилем читателя соотношением **1:1** (связь идет со стороны `Reader`).
* **Author (Авторы)**: Информация об авторах книг (`id`, `full_name`, `country`, `birth_date`). Связан с книгами соотношением **1:N ("один-ко-многим")**.
* **Book (Книги)**: Каталог книг (`id`, `title`, `pages`, `author_id`). Физически хранит `author_id` (внешний ключ на автора).
* **Reader (Читатели)**: Персональные профили читателей(`id`, `full_name`, `register_date`, `user_id`).
  * Связан **1:1** с пользователем через `user_id` (внешний ключ).
  * Связан **M:N ("многие-ко-многим")** с книгами (читатель может взять много книг, одну книгу могут взять разные читатели). Связь реализована через промежуточную таблицу ( `book_reader_association`).


Ролевая модель и безопасность:
Для защиты эндпоинтов используется кастомный класс-зависимость `RoleChecker`.
Он автоматически извлекает JWT из куки, валидирует его,
проверяет в Redis-блэклисте и ограничивает доступ по ролям:

```python
# Пример использования в роутере FastAPI:
@router.get("/protected/")
async def get_admin_books(
    current_user: dict = Depends(RoleChecker(required_roles=("admin",)))
):
    return {"message": "Welcome, admin!"}
```

Миграции (Alembic):
Если вы изменили модели базы данных, создайте и примените миграцию:
```bash
docker compose --profile main exec app alembic revision --autogenerate -m "описание"
docker compose --profile main exec app alembic upgrade head
```

Запуск тестов:
Для прогона тестов в изолированном окружении с автоматической очисткой базы данных:
```bash
docker compose --profile test up --abort-on-container-exit --renew-anon-volumes
```

### Пример User Flow: Добавление новой книги в библиотеку

Чтобы успешно добавить книгу, клиент (например, фронтенд или разработчик в Postman) должен пройти следующий путь:

1. **Шаг 1: Аутентификация (POST `/auth/login`)**
    Первый администратор создается автоматически при старте приложения.
    Выполните вход, используя `username` и `password` администратора, указанные вами в `.env`.
    Бэкенд проверяет их и возвращает JWT-токен в **HttpOnly Cookie** (`access_token`).
   
2. **Шаг 2: Создание автора (POST `/authors`)**
   Пользователь отправляет данные автора. Зависимость `RoleChecker` считывает куку из Шага 1, проверяет, что роль действительно `admin`, и разрешает создание. Бэкенд возвращает созданного автора с `id: 12`.
   
3. **Шаг 3: Создание книги (POST `/books`)**
   Пользователь отправляет данные книги, обязательно указывая `author_id: 12`, полученный на предыдущем шаге. `RoleChecker` снова валидирует куку. Книга успешно создается.


Дополнительные возможности в Swagger:

* **Для Гостей (Анонимных пользователей):**
  * Просмотр каталога книг и авторов (доступно без авторизации).
  * Регистрация нового аккаунта (автоматически создает сущность `User` и профиль `Reader` со связью 1:1, присваивая роль `reader`).
* **Для Авторизованных Читателей (роль `reader`):**
  * Просмотр/редактирование личного профиля.
  * Возможность "взять/вернуть книгу" (добавляет связь в M:N таблицу).
* **Для Администратора (роль `admin`):**
  * Полный CRUD авторов, книг и управление пользователями.
